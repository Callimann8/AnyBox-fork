# xgameruntime

## add Functional

- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - containers are stored as one file each, `<container name with / as %>.xgs`, in `%LOCALAPPDATA%\AnyBox\<TitleId>\XGameSave`; there is no cloud sync, `needsSync` is always `false`, and the requesting user, `configurationId` (only checked for null) and `syncOnDemand` are ignored, so every user of a title shares one set of saves; a missing `<TitleId>` or `LOCALAPPDATA` stops with `AbxUnsupported`
  Closes when: XUser is implemented and saves are kept per user
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - signatures, structures, error codes, the container name rules (`E_GS_INVALID_CONTAINER_NAME`), the 16 MiB update limit (`E_GS_UPDATE_TOO_BIG`), the 256 MiB per-user quota (`E_GS_QUOTA_EXCEEDED`) and `E_GS_HANDLE_EXPIRED` for an update used after it was submitted follow the public GDK documentation, not a console; the quota counts blob bytes only, and container and blob names match case-insensitively
  Closes when: measured on a console title
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - behaviour the documentation does not state: a null pointer argument returns `E_INVALIDARG`, as does an empty blob name or a second write or delete of one blob in an update; deleting a missing blob or container succeeds; `XGameSaveGetContainerInfo` on a missing container returns `S_OK` without calling back; a null display name in `XGameSaveCreateUpdate` keeps the stored one; `XGameSaveReadBlobData` with null `blobNames` and a count of 0 reads every blob; the read buffer holds the `XGameSaveBlob` array followed by each blob's name and data, and a buffer that is too small returns `E_GS_PROVIDED_BUFFER_TOO_SMALL`; the blob name length limit is not enforced; host I/O failures return `E_GS_OUT_OF_LOCAL_STORAGE` for a full disk and the Win32 error otherwise
  Closes when: measured on a console title
- [XGameSave](../../../core/libs/xdll/xgameruntime/GameSave.cpp) (xgameruntime) - a container name over 251 characters (the documented limit is 256), a blob over 4 GiB, or a file in the save folder that AnyBox did not write stops with `AbxUnsupported`
